# ADR-001: SQLite behind a repository interface

Status: accepted (greenfield scenario)

## Decision

Use SQLite (WAL) with versioned forward-only migrations, accessed only through LinkRepository.

## Rationale

Meets 'survive restart, no external DB, runs on a laptop'. A primary-key lookup is well under 1 ms, far inside the 50 ms p99 budget. The repository boundary keeps a later move to Postgres a contained change.

## Alternatives considered

- In-memory dict (loses data on restart)
- PostgreSQL (violates the no-external-DB constraint)
- Key-value file store (no transactions for counters)

## Consequences

Single-writer; horizontal scaling needs a different store (out of scope for v1).
