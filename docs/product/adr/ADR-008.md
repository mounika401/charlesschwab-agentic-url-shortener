# ADR-008: In-process token-bucket rate limiting keyed by peer address

Status: accepted (ambiguous scenario)

## Decision

TokenBucketLimiter per endpoint class; key = direct peer address; LRU-bounded memory.

## Rationale

Requester accepted per-instance state for a single-node launch. Token bucket allows short bursts while bounding sustained rate. Keying on X-Forwarded-For without a trusted proxy would let clients choose their bucket.

## Alternatives considered

- Redis shared limiter (correct across replicas, adds infrastructure now)
- Fixed window counter (boundary bursts of 2x limit)
- Reverse-proxy rate limiting (not in our control for this repo)

## Consequences

N replicas => N x limit. Behind a proxy the client key must come from a trusted forwarding hop.
